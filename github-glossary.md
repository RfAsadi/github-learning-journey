# GitHub Glossary

A reference to the key terms I am learning while exploring GitHub, open source, and software project maintenance.

## 1. Repository
A project's home on GitHub. It contains files, documentation, and the history of changes. It may also include issues, discussions, and automation.

## 2. Commit
A recorded snapshot of changes, usually accompanied by a message explaining what changed. Commits build the project's history.

## 3. Branch
A separate line of work within a repository. It allows changes to be developed without immediately changing the main branch.

## 4. Fork
A GitHub-hosted copy of another repository, linked to the original. Forks are commonly used to propose contributions to projects maintained by others.

## 5. Clone
A local or remote working copy of a Git repository, including its history. Cloning does not itself create a new GitHub repository.

## 6. Issue
A place to track a bug, propose a feature, ask a question, or organize a task.

## 7. Pull Request (PR)
A proposal to merge changes from one branch into another. It supports discussion, review, and automated checks before changes are merged.

## 8. Merge
The process of integrating changes from one branch into another.

## 9. Release
A published version of a project, often with a version number, release notes, and downloadable files.

## 10. Maintainer
Someone responsible for looking after a project. Depending on their role, maintainers may review contributions, triage issues, manage releases, and guide project direction.

## 11. Contributor
Anyone who helps a project through code, documentation, testing, bug reports, translations, design, or community support.

## How the Terms Connect
A common workflow is:

1. Someone reports a problem in an issue.
2. A contributor creates a branch and makes changes.
3. The contributor records changes in commits.
4. The contributor opens a pull request.
5. The changes are reviewed and may be merged.
6. The project may include the changes in a release.

A contributor may fork a repository before starting work. A maintainer often reviews contributions and helps guide the project.

## What I Learned
- A repository stores project files and their history.
- Commits record changes; branches separate lines of work.
- Pull requests propose changes, while merges integrate them.
- Issues help organize work.
- Releases publish versions of a project.
- Contributors help projects, and maintainers help look after them.
